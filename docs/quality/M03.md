## Review findings

Reviewer summary: M03 Party & Consent is well-architected and implements nearly all requirements correctly. P3 field encryption and tenant isolation are properly enforced, the consent ledger is append-only, and merge reversibility is handled within the 30-day window. However, a subtle bug in the role-link repointing logic on merge reversal could leave links un-reversed when no role links are moved initially or when reversing with an empty onlyKeys array. Test coverage is strong but doesn't exercise this edge case. Code quality follows SOLID principles with clean layering and appropriate use of patterns.

| Severity | Area | Finding | Status |
|---|---|---|---|
| High | merge reversal / role link repointing | Role link repointing logic has a bug when onlyKeys is an empty array. The condition `(onlyKeys && !onlyKeys.includes(...))` treats empty arrays as truthy and skips all matching links. This causes links to fail to repoint on reversal when no role links were moved during the initial merge (movedLinks.roleLinkKeys = []), or when selectively reversing a subset of links. | dismissed |
| Medium | test coverage / edge cases | Merge and reversal tests do not exercise parties with role links. Test fixtures (John and Jon) have no role links, so the role-link repointing logic (including the bug above) is never tested. AC-M03-09 requires testing that 'links moved back exactly', but the test suite does not verify this for non-empty link scenarios. | fixed |
| Low | design / abstraction | DuplicateService constructor has 8 dependencies (at the limit per CLAUDE.md: max 8 for NestJS with injected collaborators). While technically compliant, consider extracting a dedicated service for managing move/copy operations (consents, roles, household) to reduce responsibilities and improve testability. | dismissed |
