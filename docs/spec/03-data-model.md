# 03 · Data model

Ownership follows HLD §8: every fact has one system of record. This document is the conceptual model for **all** modules and the conventions every table follows. Each module LLD carries the exact DDL for its tables.

## 1. Conventions

| Rule | Detail |
|---|---|
| Keys | `id text` primary key, prefixed ULID generated by `IdGenerator` (`ten_…`, `pty_…`, `lead_…`). Prefixes make IDs self-describing in logs. |
| Tenancy | Every tenant-scoped table has `tenant_id text not null references tenant(id)`; RLS policy `tenant_id = current_setting('app.tenant_id')`; `FORCE ROW LEVEL SECURITY`; the app role `iap_app` has `NOBYPASSRLS`. `SET LOCAL app.tenant_id` is issued at the start of every transaction from the verified context (kernel `PgUnitOfWork`). |
| Audit columns | `created_at timestamptz not null default now()`, `updated_at`, `created_by text`, `version int not null default 1` (optimistic concurrency; updates use `where version = $n`). |
| Money | `<name>_paise bigint` + `currency char(3) default 'INR'`. |
| Enums | `text` with `check (col in (...))` so new values are an expand migration, not a type rewrite. |
| JSONB | Only for schema-registered payloads (proposal answers, custom fields, adapter manifests) with a `schema_id` + `schema_version` column. No EAV. |
| Personal data class | Column comment `P0`–`P3` (`comment on column … is 'P2'`). P3 columns are `bytea` ciphertext with field-level encryption (per-tenant data key) and a `_hash` column when lookup is needed. |
| Soft delete | Not used for personal data (DSR erasure must really erase); business records use status columns. |
| Partitioning | `audit_event`, `premium_due`, `message_send`, `outbox` partitioned by month once volume warrants (HLD §13); designed with `occurred_at` in the key. |
| Migrations | `apps/core/migrations/NNN_<module>_<change>.sql`, forward-only, expand → backfill → contract. |

## 2. Kernel tables (M00)

| Table | Purpose | Key columns |
|---|---|---|
| `outbox_event` | Transactional outbox (CloudEvents) | `id`, `tenant_id`, `type`, `source`, `subject`, `data jsonb`, `occurred_at`, `published_at`, `attempts`, `last_error` |
| `inbox_message` | Consumer dedup | `consumer`, `event_id` (PK pair), `processed_at` |
| `audit_event` | Append-only audit log (HLD Compliance & Audit) | `id`, `tenant_id`, `actor`, `action`, `entity_type`, `entity_id`, `occurred_at`, `trace_id`, `before_hash`, `after_hash`, `metadata jsonb` — `UPDATE`/`DELETE` revoked |
| `idempotency_record` | Idempotent writes | `tenant_id`, `key`, `request_hash`, `status`, `response jsonb`, `created_at`, `expires_at` |

## 3. Module entities

### M01 Tenant & Entitlements (system of record: Core)
- `tenant` — id, slug, kind (`ORGANISATION`,`SOLO`), status (`provisioning`,`active`,`suspended`,`offboarded`), plan_id, cell, deployment_mode (`pooled`,`dedicated`), crm_mode (`solo_lite`,`twenty`).
- `distributor_entity` (Rev 3.0) — tenant_id, entity_type (`IMF`,`BROKER`,`INDIVIDUAL_AGENT`,`CORPORATE_AGENT`), legal_name, registration_no, registration_valid_to, principal_officer_member_id.
- `tie_up_limit` — entity_type, line_of_business, max_insurers (null = market-wide); platform data, versioned by effective date (IMF 6 per line, agent 1 per line today).
- `tenant_domain` — tenant_id, host (unique), verified_at, kind (`platform_subdomain`,`custom`).
- `plan` — id, code (`SOLO`,`TEAM`,`BUSINESS`,`WHITE_LABEL`,`DEDICATED`), limits jsonb (seats, leads/month, AI credits, custom fields), features text[].
- `tenant_feature_flag` — tenant_id, flag, enabled, gated_reason.
- `tie_up` — tenant_id, insurer_id, line_of_business (`LIFE`,`HEALTH`,`MOTOR`,`GENERAL`), effective_from, effective_to (IRDAI tie-up limits per line per entity type).
- `brand_kit` — tenant_id, tokens jsonb, logo_ref, letterhead_ref, powered_by_visible.
- `usage_counter` (F99) — tenant_id, metric (`ai_credits`,`messages`,`seats`,`customers`), period, used, limit.

### M02 Distribution Network
- `org_unit` — id, tenant_id, parent_id, kind (`HEAD_OFFICE`,`REGION`,`BRANCH`,`TEAM`), name, territory_codes text[] (Composite tree).
- `member` — id, tenant_id, user_ref (Keycloak subject), display_name, phone_masked, salesperson_type (`EMPLOYEE`,`ISP`,`POSP`,`SOLO`, null for non-sellers), org_unit_id, status (`invited`,`onboarding`,`active`,`suspended`,`exited`), capacity_per_day, skills text[], languages text[].
- `member_role` — member_id, role — catalogue in [05 §1](05-requirements-traceability.md#1-requirements-that-shape-the-design).
- `licence` — member_id, kind (`POSP_LIFE`,`POSP_GENERAL`,`ISP`,…), number, valid_from, valid_to, verified_at; expiry alerts at 60/30/7 days.
- `insurer_code` — member_id, insurer_id, code.
- `leave` — member_id, from, to (routing excludes on leave).

### M03 Party & Consent (Core; P2/P3 live here only)
- `party` — id, tenant_id, kind (`PERSON`,`ORGANISATION`), display_name (P2), dob_enc (P3), gender, preferred_language, pan_hash/pan_enc (P3), status, merged_into_id.
- `contact_point` — party_id, channel (`MOBILE`,`EMAIL`,`WHATSAPP`), value_enc (P2), value_hash (lookup/dedup), verified_at, is_primary.
- `household` / `household_member` — household_id, party_id, role (`SELF`,`SPOUSE`,`CHILD`,`PARENT`,`OTHER`).
- `consent_record` — append-only ledger: party_id, purpose (`SERVICE`,`MARKETING`,`AI_PROCESSING`,`DATA_SHARING_INSURER`), channel, notice_version, granted bool, source, captured_by, occurred_at.
- `suppression` — party_id or contact hash, channel, reason (`DND`,`OPT_OUT`,`BOUNCE`,`DSR`), from, to.
- `duplicate_candidate` — pair of party ids, score, rule, status (`open`,`merged`,`dismissed`).

### M04 CRM Engagement (Twenty for org tenants; Solo-CRM-lite tables in Core for solo tenants and as the PWA cache)
- `crm_lead` — id, tenant_id, party_id, source (`WEB`,`REFERRAL`,`WALK_IN`,`CAMPAIGN`,`IMPORT`,`SOCIAL`), campaign_id, product_interest (LoB), stage (`NEW`,`CONTACTED`,`QUALIFIED`,`CONVERTED`,`LOST`), owner_member_id, org_unit_id, score, sla_due_at, lost_reason, external_ref (Twenty id), sync_state (`synced`,`pending`,`failed`).
- `crm_routing_rule` — tenant_id, priority, specification jsonb (conditions), method (`ROUND_ROBIN`,`TERRITORY`,`SKILL`,`LEAST_LOADED`), target_org_unit_id, sla_minutes, escalate_to_member_id, active.
- `crm_task` — id, tenant_id, owner_member_id, subject_type/id (lead, party, opportunity, due), kind (`CALL`,`MEETING`,`FOLLOW_UP`,`DOCUMENT`,`RENEWAL`), due_at, status (`OPEN`,`DONE`,`CANCELLED`), outcome.
- `crm_activity` — id, tenant_id, subject_type/id, kind (`CALL`,`NOTE`,`WHATSAPP`,`SMS`,`EMAIL`,`MEETING`,`STAGE_CHANGE`), summary (no P3), occurred_at, actor.
- `crm_opportunity` — id, tenant_id, lead_id, party_id, line_of_business, stage (`DISCOVERY`,`QUOTE_SHARED`,`PROPOSAL_COMPLETE`,`INSURER_PENDING`,`ISSUED`,`LOST`) — Rev 2.0 funnel; `ISSUED` only from insurer confirmation, premium_band, core_proposal_id, lost_reason.
- `crm_routing_cursor` — tenant_id, rule_id, last_member_id (round-robin state).

### M05 Product Catalogue
- `insurer` — id, name, irdai_reg_no, lines text[].
- `product` — id, insurer_id, line_of_business, name, category.
- `product_version` — id, product_id, uin, wording_version, posp_eligible bool, channel_eligibility text[], effective_from/to, status (`draft`,`active`,`withdrawn`), quote_requirements jsonb — immutable once quoted.

### M06 Advice & Quote
- `needs_analysis` — id, tenant_id, party_id, calculator (`PROTECTION`,`RETIREMENT`,`CHILD`,`HEALTH`), inputs jsonb, assumptions_version, result jsonb.
- `quote` — id, tenant_id, opportunity_id, party_id, comparison_snapshot jsonb, scope_snapshot_id, status.
- `quote_option` — quote_id, product_version_id, insurer_quote_id, route (`API`,`MANUAL`), premium_paise, gst_paise, riders jsonb, coverage jsonb, exclusions_ref, valid_until, selected bool, selection_rationale.
- `benefit_illustration` — quote_id, document_ref, shared_at, acknowledged_at, ack_channel.
- `advice_record` — party_id, quotes compared, suitability_note, disclosures shown, scope_snapshot.

### M07 Book & Retention
- `held_policy` — id, tenant_id, party_id, insurer_id, product_version_id, policy_number_enc/hash/last4, status (`IN_FORCE`,`GRACE`,`LAPSED`,`PAID_UP`,`SURRENDERED`,`MATURED`), sum_assured_enc (P3), premium_paise, frequency, start_date, renewal_date, source (`IMPORT`,`ISSUANCE`,`MANUAL`), servicing_member_id.
- `servicing_request` (F74 lite) — id, tenant_id, party_id, policy_id, type, insurer_reference, status, follow_up_date, insurer_link, notes.
- `premium_schedule` — policy_id, frequency, next_due_date, grace_days.
- `premium_due` — id, tenant_id, policy_id, due_date, grace_end, amount_paise, status (`UPCOMING`,`DUE`,`IN_GRACE`,`PAID`,`LAPSED`,`REVIVED`), outcome, assigned_member_id, source (`COMPUTED`,`INSURER`).
- `book_import_batch` / `book_import_row` — batch status, row raw jsonb, mapped jsonb, confidence per field, review status.

### M08 Integration Hub
- `adapter_registration` — tenant_id, insurer_id, adapter_package, version, capability_manifest jsonb, credentials_ref, enabled, certified_at.
- `external_call` — id, tenant_id, counterparty, operation, idempotency_key, status (`PENDING`,`OK`,`FAILED`,`UNKNOWN`), attempts, request_ref, response_ref, latency_ms.
- `dead_letter` — id, tenant_id, source, payload jsonb, error, owner, status (`open`,`replayed`,`discarded`).

### M09 Proposal & Issuance
- `proposal` — id, tenant_id, party_id, quote_id, insurer_form_version_id, status (`DRAFT`,`READY`,`SUBMITTED`,`UNKNOWN`,`PAYMENT_PENDING`,`PAID`,`ISSUED`,`DECLINED`,`WITHDRAWN`), route (`API`,`ASSISTED`), idempotency_key, insurer_proposal_no, frozen_snapshot_enc (P3), submitted_at.
- `proposal_party` — proposal_id, party_id, role (`PROPOSER`,`INSURED`,`PAYER`,`NOMINEE`); multiple insured allowed.
- `submission_attempt` — proposal_id, attempt_no, idempotency_key, route, status (`PENDING`,`ACCEPTED`,`REJECTED`,`UNKNOWN`), insurer_reference, evidence_ref.
- `proposal_answer` — party facts with source, confirmer, confirmed_at (health answers customer-only).
- `payment_reference` — proposal_id, link_ref, status, paid_at (platform never holds premium).
- `policy_sale` — proposal_id, policy_number, issued_at, source_event_id.

### M10 Commission & Performance
- `commission_rule` — insurer_id, product_id, line, year, rate_bps, type (`FIRST_YEAR`,`RENEWAL`), source_ref, status (maker-checker `pending`,`approved`).
- `commission_expected` / `commission_received` — per policy and period; `reconciliation_item` with variance.
- `persistency_snapshot` — member/org_unit cohort ratios (13th, 25th, …, 61st month).

### M11 Compliance & Audit
- `ad_approval` — reference, insurer_id, asset_ref, valid_from/to, status.
- `content_approval` — content_ref, version, checksum, state (`draft`,`in_review`,`approved`,`rejected`,`published`), approver, ad_approval_id.
- `dsr_case` — party_id, kind (`ACCESS`,`CORRECTION`,`ERASURE`,`GRIEVANCE`), state, due_at, evidence_ref.

### M12 Engagement Orchestration
- `reminder_schedule` — due_id/policy_id, offsets (90/60/30/15 days), channel plan.
- `message_send` — id, tenant_id, party_id, channel, template_id, purpose, status (`QUEUED`,`SUPPRESSED`,`SENT`,`DELIVERED`,`FAILED`), consent_check_at, provider_ref.
- `campaign` / `segment` — segment specification jsonb, schedule, template, attribution.

### M13 Documents & AI Gateway
- `document` — id, tenant_id, owner (party/proposal/policy), object_key, classification (P-class), checksum, av_status, retention_class.
- `ai_skill_config` — tenant_id, skill (`POLICY_READER`,`VERNACULAR_DRAFT`,`VOICE_TO_CRM`,`PRODUCT_ASSISTANT`), enabled, model_version, prompt_version, credit_limit.
- `ai_interaction` — skill, versions, input_ref, output jsonb, reviewer_decision, cost_micros.

## 4. Projections to Twenty (HLD §8)

| Core entity | Twenty object | Fields projected | Withheld |
|---|---|---|---|
| party | Person | name, masked phone, email, language, `core_party_id`, `can_contact` + channels | DOB, IDs, address, household |
| held_policy | Policy Summary (read-only) | insurer, product, masked policy no., status, next due, renewal date | sum assured, nominee, medical |
| premium_due | Premium Due (read-only) | due date, grace end, outcome, assigned seller | amount components |
| proposal | Opportunity stage + premium band | stage, band | premium components, declarations, documents |

Projection writes go through the outbox → CRM sync worker → CRM Port; Twenty webhooks come back through the inbox (dedup on event id) — field ownership decides conflicts.
